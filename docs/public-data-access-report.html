Reference GIS Database

Data Availability & Design Report — Phase 1: Texas
Prepared by: Geomatics · Date: November 13, 2026 · Audience: REPO (Business Development & Estimating)

1. Purpose

REPO needs project-risk data for sites under estimate, even when the owner or client has not provided it. This report lists the data REPO requested, which of it is publicly available at no cost, how it will be stored and kept current, what is not available, and how team members will view it in QGIS.

The data lives in the reference database: public GIS layers gathered in one place and read-only for users. Geomatics maintains it.

3.3 Keeping the Data Current

Weekly check. Once a week, each source is asked for its current version or last-updated date. Nothing is downloaded. The result is recorded in public.source_checks, and any layer with newer data is flagged for the maintainers.

Loads. A Geomatics maintainer starts each load. The new data goes into a staging area first and replaces the live layer in a single step, so users never see a half-loaded layer. Every load is recorded in public.load_runs.

3.4 Electric Transmission Lines

The federal public portal (HIFLD Open) was shut down on August 26, 2025, but its transmission line data was archived and is still free to download. The database carries two separate layers, so users can compare them:

LayerStrengthLimitation
energy.transmission_lines_hifld Federal dataset compiled by Oak Ridge National Laboratory; consistent national coverage of 69–765 kV lines Frozen. No updates after February 2025, so newer lines are missing
energy.transmission_lines_osm Updated continuously by mappers; can show lines built after 2025 Volunteer data with uneven completeness and accuracy; not an official source
Both layers are for screening and reference only. Where they disagree, or where a line affects a project, confirm its location and voltage with the utility.

5. Data Stored Outside the Database (AWS S3 or S3 compatible alternative)

5.1 What goes to S3

Topography (USGS 3DEP 1-meter elevation models).

5.2 Why it cannot be stored in the database

  • Size. Texas covers about 268,000 square miles. At 1-meter resolution, that is roughly 690 billion elevation cells — on the order of 2.8 TB uncompressed. That is far larger than every other layer combined.
  • Data type. Elevation models are rasters (grids of cells), not points, lines, or polygons. PostGIS is built for vector data; storing terabytes of raster in it would slow backups, restores, and the database itself.
  • Viewing. Stored as Cloud Optimized GeoTIFFs (COGs) in S3, QGIS downloads only the part of the file that is on screen. No one downloads the whole dataset.
  • Cost. Object storage costs far less per gigabyte than database storage.

5.3 Reference table

The database keeps a record of every elevation file, including its footprint, so users can see coverage in QGIS and find the right file. The table is storage.raster_assets:

ColumnHolds
idUnique ID for the record
layerWhich raster layer the file belongs to, e.g. dem_1m
storage_systemWhere the file is stored, e.g. s3
storage_keyThe file's path in that storage, e.g. dem_1m/tx/USGS_1M_14_x50y327.tif
sourceWhere it came from, e.g. USGS 3DEP
source_dateDate published by the source
loaded_atWhen it was added
footprintTile outline, drawn as a polygon in QGIS

A single mosaic file (dem_1m/tx/texas_dem.vrt) is also stored with the tiles. It points to every tile so QGIS can open all of Texas as one layer.

6. How the Reference Database Fits with Atlas

Atlas is the Geomatics department's project application. The reference database is part of it: one PostgreSQL instance holds two separate databases, and the Atlas code includes the reference loaders.

Solid lines: the Atlas application. Dashed blue lines: Geomatics QGIS connections. Gold lines: reference loads and REPO access.

PartRole
atlas databaseGeomatics working data: projects, tasks, deliverables, project GIS and survey data, department standards. Not visible to REPO users.
reference databasePublic GIS layers for REPO and Geomatics. Read-only for users; only Geomatics maintainers load data.
Atlas applicationHolds the reference loaders and update checks. Until the Atlas app is released, maintainers run the same loaders from their own computers. After release, a maintainer-only page shows each layer's last load and any available updates, with a button to start a load.
AWS S3Elevation rasters, too large for the database. The reference database keeps a link to every file.
The two databases share one PostgreSQL instance but stay separate: REPO users are granted access to reference only, and reference loads cannot affect Atlas data. The instance's automatic backups cover both databases.

7. Accessing the Data in QGIS

7.1 Database layers (PostGIS)

Each user sets up the connection once. Access is read-only for REPO users; only maintainers can edit.

QGIS → Browser panel → right-click "PostgreSQL" → New Connection

  Name:      Reference
  Host:      <database host, provided by Geomatics>
  Port:      25060
  Database:  reference
  SSL mode:  verify-full
  Auth:      user's own login

verify-full needs the database's CA certificate (a small file that lets QGIS confirm it is talking to the real database). Geomatics provides the file and where to save it.

After connecting, every schema and table appears in the Browser panel. Drag a table onto the map to add it. Maintainers save each layer's style to the database as its default style (stored in public.layer_styles), so every user sees the same symbology when the layer loads.

Port 25060 was tested from a company work laptop on November 13, 2026, and the connection succeeded.

7.2 Elevation data (S3)

Step 1 — Credentials (once per user, no admin rights needed).

QGIS → Settings → Options → System → Environment → Use custom variables

  AWS_ACCESS_KEY_ID      = <read-only key>
  AWS_SECRET_ACCESS_KEY  = <read-only secret>
  AWS_DEFAULT_REGION     = <bucket region>

Restart QGIS after saving.

Step 2 — Add the elevation layer.

QGIS → Layer → Data Source Manager → Raster

  Source type:  Protocol: HTTP(S), cloud, etc.
  Type:         AWS S3
  Bucket:       <bucket name, provided by Geomatics>
  Object key:   dem_1m/tx/texas_dem.vrt

Step 3 (optional) — Find a specific tile. Add storage.raster_assets from the Reference connection to see tile footprints. Each record holds the storage location and path for that tile.

QGIS streams only the part of the elevation data in the current map view. Users do not download the full dataset.
